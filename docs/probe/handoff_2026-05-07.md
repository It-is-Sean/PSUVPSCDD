## Current SCRREAM data products

All current formal SCRREAM adapter data uses `target_source=mesh_complete`:

1. Read two-view pairs from `data/scrream/scrream_n2_list.json`.
2. Use the two pair RGB frames as VGGT adapter inputs.
3. Read the current sequence `meta.txt` and select only matching registered `sceneXX/meshes/*.obj`.
4. Sample selected mesh surfaces proportional to surface area.
5. Voxel-deduplicate and cache per-sequence/meta-hash mesh reservoirs under `experiments/probe3d/adapter_data/mesh_cache/`.
6. Crop mesh points to the union frustum of the two input views.
7. Transform the target to the first input camera coordinates.
8. FPS / pad to a fixed target count.

## Slurm training scripts

`slurm/scrream_mesh_complete_mlp_train.sbatch` now supports single-node multi-GPU training:

- one visible GPU: launches normal `python`
- multiple visible GPUs: launches `torchrun --standalone --nnodes=1 --nproc_per_node=$SCRREAM_GPUS_PER_NODE`

For future multi-GPU runs, prefer setting `SCRREAM_EPOCHS` instead of manually computing `SCRREAM_MAX_STEPS`; the script computes:

```text
max_steps = ceil(train_count * SCRREAM_EPOCHS / (batch_size_per_gpu * gpu_count))
```

Example four-GPU launch:

```bash
SCRREAM_GPUS_PER_NODE=4 \
SCRREAM_EPOCHS=50 \
SCRREAM_ADAPTER_DATA=experiments/probe3d/adapter_data/scrream_mesh_complete_n2_adapter_seed17_tp20000_ms500000_trainplus_test.pt \
SCRREAM_OUTPUT_DIR=experiments/probe3d/result/scrream_mesh_complete_n2_trainplus_test_tp20000_ms500000_mlp_l4_nova_flow_seed17_ddp4 \
SCRREAM_FEATURE_CACHE_DIR=experiments/probe3d/feature_cache/scrream_mesh_complete_n2_trainplus_test_tp20000_ms500000_vggt23 \
SCRREAM_SWANLAB=1 \
SCRREAM_NUM_QUERIES=20000 \
sbatch --qos=high --nodelist=<node-with-free-a100s> --gres=gpu:a100:4 --mem=96G \
  slurm/scrream_mesh_complete_mlp_train.sbatch
```
